## 3. 실행 방법

자세한 건 `docs/dev-setup.md`.

```bash
# 서버 (PC)
cd server && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env                       # VISION_PROVIDER=mock
.venv/bin/python -m pytest -q              # 40 passed
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 --env-file .env

# 앱 (Expo Go)
cd app && npm install --legacy-peer-deps
cp .env.example .env                       # EXPO_PUBLIC_API_URL=http://<PC LAN IP>:8000
npx expo start -c                          # 폰과 PC 같은 Wi-Fi

# 웹 미리보기
cd app && npx expo export -p web --output-dir /tmp/sallim-web && npx serve /tmp/sallim-web -l 4173
```

- `EXPO_PUBLIC_API_URL`을 비우면 mock 모드(화면에 '예시 데이터' 표시).
- **WSL2에서 서버를 돌리면 폰에서 WSL IP가 안 보임** → `.wslconfig`에 `networkingMode=mirrored` 또는 `netsh portproxy` + 방화벽 8000 허용 (dev-setup 2절).

## 4. 결정한 것과 이유 / 사람이 정해야 할 것

**결정 (lead)**
- **오류 형식**: 모든 비 2xx 응답을 `{"error":{"code","message"}}`로. code 목록은 `shared/api-types.ts` `ErrorCode`, 계약 테스트가 서버 코드와 목록 일치를 검사. 앱은 code로 상태 화면을 고르고, 응답이 없거나 15초 초과면 `network`.
- **크기·시간 제한**: 이미지 3MB(앱은 긴 변 1024px JPEG로 줄여 보냄, 보통 0.5MB 이하), 요청 본문은 Content-Length로 먼저 거름. VLM 호출은 연결 5초·전체 12초 → 504 `provider_timeout`. "3초 안에 답" 목표 대비 실제 VLM 속도는 미측정.
- **`server/.env` 추적 해제**: 레포에 올라가 있었음(내용은 mock 설정뿐, 키 없음). 키를 넣는 순간 유출되므로 `.gitignore`에 `.env` 추가. 과거 커밋에는 남아 있음(비밀 없음).
- **추가 의존성 승인**: `react-native-worklets`(reanimated 4 필수), Pretendard 1.3.9 OTF 3종(OFL-1.1, 파일당 1.5MB, 라이선스 동봉).
- **개인정보 문구**: "사진은 바로 지워진다"는 검증 안 된 표현을 빼고 "서버에 저장하지 않음 + AI 분석 서비스로 보내질 수 있음"으로 통일(앱 설정·ux-copy·스토어·방침 초안). 동네 id는 요청마다 서버로 가지만 저장 안 함.
- **결과 첫 화면**: 결과가 뜨면 경고(예시 데이터·확신 낮음)부터 보이게 스크롤 — 잘못된 안내로 오인될 위험이라 QA 최우선 처리.
- **테마**: 웹에서도 화면 모드가 실제로 바뀌도록 앱 상태(`useScheme`)로 관리 — 처음엔 "웹은 안내 문구만"으로 정했으나 coder 제안이 더 작고 정확해서 바꿈.

**사람이 정해야 할 것**
1. 실제 VLM 프로바이더(claude/gemini)·모델·월 한도 — 정해지면 스토어 방침의 `[미정]` 업체명 채우기.
2. 서버 호스팅·HTTPS 여부 (HTTP면 `app.json` `usesCleartextTraffic: true` 유지).
3. 공개 서버라면 `/ask` 인증·요청 제한 (현재 없음 → 누구나 호출해 VLM 과금 가능). 본문 크기 제한은 Content-Length만 봄 → 프록시에서도 제한 권장.
4. 문의 경로(이메일 등) — 설정에 '준비 중' 문구만 있음.
5. 운영 주체명·접속 로그 정책 (방침 초안 `[확인 필요]`).

## 5. 알려진 문제 / 미검증

- **실기기 전부 미검증**: 카메라 촬영·앨범, 햅틱, 60fps, safe area, 글자 200%, TalkBack, 네이티브 테마 전환.
- **폰 → PC 서버 연결 미검증**: PC 안 웹 빌드(`EXPO_PUBLIC_API_URL=localhost`)로 `/regions`·`/schedule`·`POST /ask` 실호출, 실데이터 결과 카드·동네 안내 표시, 페이지 오류 0 확인까지만.
- **스플래시 다크**: `app.json` `splash.dark`만 넣음, 빌드에 반영되는지 미확인(필요하면 `expo-splash-screen` 플러그인 설정).
- **Mock 프로바이더는 실사진을 항상 unknown** 처리 → mock 서버로 폰 테스트 시 촬영 결과는 늘 "알 수 없음"이 정상. 촬영 흐름의 성공 결과는 실제 VLM에서만 확인 가능.
- 테마 전환은 즉시 바뀜(명세의 180ms 크로스페이드 미구현, 경미).
- 오류 상태 화면들은 브라우저 합성 응답으로만 확인(실 네트워크 단절 미확인).
