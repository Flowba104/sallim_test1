# 상태 화면 명세

살림 노트(A) 기준. [다섯 화면 보기](states/index.html). 모든 상태에서 품목·일정이 확정됐는지 글자로 구분한다.

| 상태 | API/조건 | 화면 | 다음 행동 |
|---|---|---|---|
| 로딩 | ask 또는 followup 처리 중 | 현재 단계와 작업 설명, 확정 안내 숨김. 3초를 보장하는 카운트다운 없음 | 취소 후 촬영/질문으로 돌아가기. 취소된 응답을 새 결과로 덮어쓰지 않기 |
| 인식 실패 | item_key=null, confident=false | “이 물건은 아직 찾지 못했어요.” 카테고리·절차·요일 숨김 | 다시 촬영 / 이름으로 물어보기 |
| 확신 낮음 | item_key는 존재, confident=false | 경고+“후보” 글자. 확정 표현 대신 “보여요”. 다음 요일은 이 후보가 맞는 경우임을 명시 | 재질 표시 다시 촬영 / 텍스트 확인. 사용자의 클릭만으로 confident=true로 바꾸지 않기 |
| 네트워크 오류 | 타임아웃/오프라인/서버 오류 | 새 결과를 못 받았음을 표시. 입력 질문·지역 유지. 원시 스택·API 내부정보 숨김 | 같은 요청 재시도 / 입력 수정. followup 실패면 이전 확정 답은 유지하되 새 답으로 표시하지 않기 |
| 빈 동네 목록 | GET /regions → [] | 지원 지역이 아직 없다고 안내. 관악구로 임의 선택 금지 | 다시 불러오기. 지역 의존 질문·촬영 요청 비활성화 |

- `AskResponse.note`는 배출 요일 바로 아래, `ScheduleResponse.note`는 주간 표 아래. `null`/미제공이면 보조문구를 만들어 채우지 않는다.
- `next_days=[]`, `time=null`: “배출 요일 확인 필요” / “배출 시간 확인 필요”. 일반적인 빈 배열만으로 “오늘 배출 금지”라고 단정하지 않는다. 연구 데이터에서 확인된 관악구 토요일 금지는 별도 사실이다.
- 로딩은 텍스트·진행 상태를 함께 제공한다. reduced-motion이면 회전 정지. 앱에서는 상태 변화만 스크린리더에 알리고 반복 회전은 숨긴다.
- 모든 주요 조작 48px 이상. 오류는 아이콘+제목+설명으로 표시한다. 빨간색만으로 의미를 전달하지 않는다.
- HTML의 재시도는 데모 메시지만 표시한다. 취소·재시도·실제 요청 보존 동작은 Expo 구현 때 연결한다.
