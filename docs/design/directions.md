사진 → 품목 → 배출 순서 → 동네 일정이 한눈에 이어지는 결과 카드가 중심이다. 채팅 말풍선, 캐릭터, 보상 점수는 사용하지 않는다. 아래 네 방향은 초기 비교안이다. 2026-11-06 MISSION v2 및 lead MSG-0003에서 추천안 A `warm-note`가 이번 구현 방향으로 확정됐다.

## 공통 화면 계약

- ① 동네 선택 ② 오늘 배출 홈 ③ 촬영 ④ 결과 카드 ⑤ 예/아니오 되묻기 ⑥ 텍스트 질문. 각 방향은 이 여섯 화면을 같은 데이터로 비교한다.
- 결과: `item_name`, `category`(아이콘+글자), `answer`, `steps`, `next_days`, `time`, `sources`(제목·링크·확인일), `confident=false` 경고, `follow_up`을 표현한다. 품목 미상은 임의 분류하지 않는다.
- 홈: `today`, `today_categories`, `week`, `time`, `sources`. 빈 값은 “확인 필요”로 표시하며 빈 요일 배열을 배출 불가로 단정하지 않는다.
- 동네는 서울특별시 관악구. researcher 검증 전 요일·시간은 **디자인 예시**이며 실제 안내로 단정하지 않는다. 검증되면 출처와 함께 교체한다.
- 본문 대비 4.5:1 이상, 모든 조작 영역 최소 48×48, 본문 16px, 보조 12px 이상. 색 외에 아이콘·글자를 함께 쓴다.
- HTML은 방향마다 단일 파일, CSS·SVG·데모 동작 포함, 외부 이미지 없음. 온라인 폰트 실패 시 시스템 한글 산세리프 대체. 실제 카메라·API 호출은 하지 않는 디자인 초안이다.

## 선택 기준

한 번에 읽히는 결과, 동네 데이터의 불확실성을 숨기지 않는 안내, Expo로 옮기기 쉬운 구성, 브랜드 기억성을 비교한다. 기존 네 안 비교 결과는 compare.md, 이번 구현 확정안은 A이며 상세 토큰은 tokens.json v2.0.0을 따른다.
